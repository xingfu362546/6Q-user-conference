# 任务数据 · 小程序 ↔ OA-PC 互通（草案）

> 用户要求（2026-06-03）：**小程序与 PC 中任务数据互通**，非两套数据。

## 单一数据源

| 对象 | 说明 |
|------|------|
| **考核计划** | HR 在 OA-PC 创建/发放；全员唯一周期键 |
| **考核任务** | 计划 × 员工 = 一条任务 ID（**全端共用**） |
| **任务数据** | KR、自评、步骤进度、状态、分数 — **同一 JSON/表结构** |

```
        ┌─────────────┐
        │  后端 API    │  ← 单一事实来源
        └──────┬──────┘
     ┌─────────┼─────────┐
     ▼         ▼         ▼
 小程序填表  OA-PC HR   OA/小程序上级评
  (员工)     计划明细    (上级)
```

## 互通场景

| 场景 | 行为 |
|------|------|
| 员工小程序 Step3 保存 | OA 计划明细即时可见「填写中」、部门筛选同步 |
| 员工改一半关小程序，开 PC | **不支持 PC 员工填表？** — 待确认；若仅小程序填，PC 只读查看 |
| 上级 OA 评完 | 小程序员工「过往/结果」可见上级分 |
| HR 解锁/退回 | 双端任务状态、断点步骤 **同一字段** |
| 6Q3J 导入 | HR/系统在 PC 写入；小程序 **只读** 拉同任务 ID 数据 |

## 步骤进度同步

- 字段：`current_step`（1–8 月 / 1–11 季）、`completed_steps[]`、`draft_payload`
- 任一端 **Next/保存** → 写服务端；另一端打开 **拉最新** + 定位断点（#14-A、解锁续填）

## MVP 员工填表（已确认 B）

- 步骤条/草稿/状态 **共用 API**
- 冲突：后保存 wins + 轻提示
