## 1. 评分确认（计划截止 + 双端步骤）

### 1.1 确认人

| 决策 | 说明 |
|------|------|
| **员工 + 直接上级** 双方必须确认 | 不含分管单独确认节点 |
| 员工 **可见** 直接上级分数 **与** 分管领导分数 | 修订 v1.0「员工不可见上级分」——**仅在评分完成后的确认阶段可见** |
| 分管 **必须录入分数** | 与上级分列；**同人合并**（上级=分管）时只录一次，两列同值（`mergedReview`） |

### 1.2 计划字段

| 字段 | 说明 |
|------|------|
| `confirmDeadline` | **单个**「确认评分截止」，员工与上级共用 |
| 开启时机 | **上级评完 + 分管评完**（或合并评完成）→ 状态 **待确认** |
| 超时 | **仅催办**，状态仍为待确认 |
| 阻塞 | **不进奖金结算 / 不归档**，直到双方都确认 |

### 1.3 任务状态（粗粒度 · 小程序 / Web 待办一致）

```
填写中 → 待上级评 → 待分管评 → 待确认 → 已完成
```

- 逾期、退回单独 badge  
- 待确认页：**只读** + **一个「确认」按钮**

## 4. 退回至员工

| 项 | 决策 |
|----|------|
| **操作人** | **R3**：直接上级（评分页）+ **HR**（计划明细） |
| **可退范围** | **确认完成之前均可退**（填写中 / 已提交 / 评分中 / 待确认） |
| **不可退** | 员工 + 上级 **双方已确认** 之后 |
| **退回后** | **断点续改**（#14-A）；**已填数据保留**，不作废重走 |
| **退回原因** | 必填（默认；员工可见） |
| **评分草稿** | 退回后上级/分管已录分数 **保留为草稿**；员工再提交后重新进入评分/确认流程（待实现时细化 UI） |

## 5. 全量人员绩效结果明细（HR + 部门负责人）

### 5.1 权限

| 角色 | 范围 |
|------|------|
| **HR · 绩效管理** | 全量（P1） |
| **部门负责人** | **仅本部门** 下属（P3） |
| 薪酬 | 本页不含专属入口；奖金仍走 **薪酬结算页**（可链过去） |

### 5.2 列表粒度

- **G1**：一行 = **计划 × 员工**

### 5.3 字段（v1.1 定稿）

计划名称/周期、姓名、工号、部门、职级、范围包、任务状态（含待确认）、自评总分、**上级分 / 分管分 / 总得分**、确认态（员工✓ / 上级✓）、退回次数、最近退回原因。

**不含奖金排名/奖扣**（奖扣仅在薪酬结算页；部门负责人 v1 也不可见）。

### 5.4 筛选（全加）

计划、部门、姓名关键字、职级、任务状态、**范围包**、**确认是否超时**、**是否已结算奖金**
