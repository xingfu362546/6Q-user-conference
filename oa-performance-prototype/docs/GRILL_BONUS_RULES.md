# HR · 绩效奖金规则 · 需求规格

> **日期**：2026-06-03  
> **状态**：Grill 已确认 · 原型已更新  
> **关联**：`hr-bonus-rules-list.html`、`hr-bonus-rule-edit.html`、`hr-plan-detail.html`

---

## 1. 业务目标

绩效奖金在 **绩效总得分** 基础上，结合 **同范围包 · 同职级** 内的 **排名规则** 进行加奖或扣减。规则由 HR 配置，计划绑定时引用；**仅 HR / 薪酬** 可见，员工端不可见。

---

## 2. Grill 决策（2026-06-03）

| # | 议题 | 决策 |
|---|------|------|
| Q1 | 同分处理 | **并列同排名**（同分同名次；下一名次跳过，如两人并列第1则下一人为第3） |
| Q2 | 扣减档 | **末1、末2、末N 均可配置**，支持多档扣减 |
| Q3 | 金额模式 | **固定金额 + 得分比例%** 两种（MVP 均支持） |
| Q4 | 可见性 & 结算时机 | **仅 HR / 薪酬** 可见；在 **计划明细** 体现；**实时结算** 已结束评分的待办 |
| Q5 | 同职级启用唯一 | **每条规则绑定一个职级**；同职级 + 适用类型重叠时 **至多一条启用**；不同职级可并行启用 |

### 4.3 按职级配置 · 同职级启用唯一（Q5 · 2026-06-03 确认）

规则库按 **适用职级** 拆分，支持总监 / 经理 / 主管 / 职员 **各自独立** 的奖扣档位：

| 规则 | 说明 |
|------|------|
| **粒度** | 每条规则 `level` = 一个职级；不同职级可配置不同加奖/扣减档 |
| **启用互斥** | 同一 `level` 且 **适用类型重叠**（month↔month、quarter↔quarter、both↔任意）时，`status=enabled` **最多 1 条** |
| **冲突处理** | 保存时设为「启用」且与同职级已有启用规则冲突 → **阻止保存**，提示冲突规则名称 |
| **停用不限** | 同职级可保留多条 `disabled` 历史版本（如「职员轻量·旧版」） |
| **计划结算** | 计划 **不绑单条规则**；引擎按 `planType + 员工职级` 自动匹配启用规则 |
| **排名单元** | 仍为：同计划 · 同范围包 · **同职级** 内排名（规则只决定奖扣档，不改变分组） |

> 示例：月度计划下可同时启用「总监」「经理」「主管」「职员」四条规则；不能再启用第二条「职员·月度」规则，须先停用现有职员规则。

> 月度「经理」与季度「经理」可同时启用（适用类型不重叠）。

### 4.1 结算准入条件

个人纳入排名奖扣计算，须同时满足：

1. 员工已提交考核表  
2. **直接上级** 已完成评分  
3. **分管领导** 已完成评分

未满足者显示「待结算」及阻塞原因（待上级 / 待分管领导），不参与当次排名。

### 4.2 可见范围

| 角色 | 奖金排名/奖扣 |
|------|----------------|
| 员工 | ❌ 不可见 |
| 直接上级 | ❌ 不可见 |
| HR · 绩效管理 | ✅ 计划内试算/结算 |
| HR · 薪酬 | ✅ 薪酬结算视图 |

## 3. 排名单元

| 维度 | 说明 |
|------|------|
| 计划 | 同一条考核计划 |
| 范围包 | 同一范围包（GRILL_HR_SCOPE） |
| 职级 | 总监 / 经理 / 主管 / 职员 分组 |

**排序依据**：绩效 **总得分**（降序）。  
**最低成团人数**：同单元 < N 人时不排名（默认 3）。

---

## 4. 规则结构

### 加奖档（可配置多档）

- 第 N 名 · 固定金额 或 得分比例%

### 扣减档（可配置多档）

- 末 1 / 末 2 / 末 N · 固定金额 或 得分比例%

### 计算公式

```
个人奖扣调整 = Σ(命中加奖档) − Σ(命中扣减档)
```

> 基础奖金与薪酬系统对接为二期；MVP 展示 **排名奖扣调整额**。

---

## 5. 与计划的关系

1. HR 按 **职级** 维护多条奖金规则 → 新建计划步骤 3 预览各职级匹配情况  
2. 计划明细 · **奖金实时结算**：按员工职级自动套规则，同范围包·同职级内排名  
3. 薪酬模块可查看同计划结算结果（只读）

## 7. 上级与分管同人合并（2026-06-03 确认）

当某员工的 **直接上级** 与 **分管领导** 为同一人时：

| 维度 | 规则 |
|------|------|
| 待办 | 仅生成 **一条** 待评任务（合并节点） |
| 评分权重 | 一次评分同时计入上级 40% + 分管 40% = **80%**（余下 20% 为员工自评等） |
| 审批流 | 上级节点提交后，分管节点 **自动粘贴相同分数并完结**（`mergedReview=true`） |
| 退回 | 任一节点退回时，两节点联动退回员工 |
| 奖金结算 | 上级评完即视为分管完成，可纳入实时排名（结算表标注「合并评 / 自动粘贴」） |

原型演示：`PLAN_SETTLEMENT_ROWS` 中 **韩梅** 为合并评样例。
