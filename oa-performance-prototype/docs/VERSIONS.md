# 原型版本记录

## v1.5.2（2026-11-12）

按《评审-v1.5.0-PC端-2026-11-12》收敛。这一版只做两件事：补齐开发需要的规则，改对应的原型页面。原型页面上新增的区块都用绿色 `v1.5.2` 标签，便于按版本追溯。

### 一、补的规则

改的条款：

| 条款 | 改成什么 | 为什么 |
| --- | --- | --- |
| FR-003 | 季度按 20/40/40，分管未填或 0 分也不回退；月度固定 20/80，分管不参与 | 原文没限定周期，开发会按字面把月度也改成 20/40/40，月度最高只能到 60% |
| FR-004 | 季度减分同权重；月度减分沿用上级单人核定 | 同上 |
| FR-007 | 专项单条得分按上级 30 + 分管 30 + 人才开发部 40 加权；三方缺一方该条待评定；旧数据只有最终得分时直接采信 | 原文说只用最终得分，上级和分管填了不参与，业务上说不通 |
| FR-013 | 确认页固定五项：计算总分、上级核定、分管核定、HR 最终总分、采用分；采用分按 HR 最终 → 分管核定 → 计算总分取值 | 原文四项合并了「上级/分管核定」，开发找不到上级核定取哪个数 |
| FR-024 | 待确认只显示员工和分管。上级提交即确认，不再出现在待确认 | 现网 `score` 分支直接置上级已确认，原文假设的「上级未确认」永远不会出现 |
| FR-026 | 导出前先打开与预览相同的只读整表；空区块按任务创建时的模板快照读取 | 原导出只截局部，且模板被改后导出结构与员工看到的不一致 |

新增的条款：

- **FR-027 精度**：行综合分不单独取整；工作成果小计、减分小计、核定总分各保留 1 位（HALF_UP）；落库与展示同口径。
- **FR-028 有效分**：退至后，所选节点及其后的已提交分数转为「作废快照」，原格显示并标「已作废」；计算、确认、结果、导出、奖金只取有效分。
- **FR-029 确认页字段契约**：五项字段各自的数据来源和缺失时怎么显示，一次写死。
- **FR-030 评价关系优先级**：发放取评价关系表；表空回退自动解析并提示；存量按最近任务回填；单任务改派不回写关系表；离职不自动改。
- **FR-031 失效落点与影响面**：失效只落在当前计划的待办上。只改当前计划的名单快照和这次发放的范围包；其他计划不变，范围包模板不改。完成率分母减失效人数；结果、催办、奖金、待办、统计都排除失效；已失效只读。
- **FR-032 保存不覆盖核定分**：任何评分保存（含自动保存）不得覆盖分管核定分；HR 最终分独立字段；草稿只写草稿字段。
- **FR-033 权限与幂等**：后端从登录态取角色并校验归属；非法状态明确报错；退至、失效、恢复、改分、导入幂等。
- **FR-034 计划编辑生效规则**：未关闭才可改；名称全库唯一；允许改到过去但二次确认并提示影响人数；写操作日志。

配套交付物：`specs/001-perf-next-batch/dev-delivery.md`（前端路由、后端落点、表与迁移、灰度回滚、原型占位）、`contracts/api.md`（接口清单）、`data-model.md` 字段到表列映射、`contracts/score-rules.md` 7 个边界样例、`tasks.md` 开发任务 D01–D11。

## v1.5.1（2026-11-11）

接在 v1.5.0 之后，只改计划明细上的四项操作。

1. 导出图片先打开和「预览全部」一样的整表，确认后再导出，不再只下载局部区块。
2. 改总分在同一个弹窗里填写分数和原因后保存。
3. 离开初始节点后才显示「退至」。用节点步骤选择已经走过、且不是当前所在的节点，不能手输。
4. 失效状态用红色标出，并把员工从当时的已发放范围包移除。恢复是加回那个范围包，并重新发放同一张待办到未开始。一个人同时只在一个范围包里。

## v1.4.0 变更摘要

> 详见 [GRILL_WORKFLOW.md](./GRILL_WORKFLOW.md)
