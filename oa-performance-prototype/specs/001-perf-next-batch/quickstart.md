# Quickstart: 绩效下版本验收

**Feature**: `specs/001-perf-next-batch`  
**Date**: 2026-11-10

先看 [计分约定](contracts/score-rules.md) 和 [页面行为](contracts/ui-surfaces.md)。下面只写怎么打开原型、做哪几步、看到什么算过。

## 准备

用浏览器直接打开文件，不需要启动服务。

- OA 入口：`oa-performance-prototype/prototype/oa-pc/index.html`
- 计分自测：在 `oa-performance-prototype/prototype/assets` 对 `perf-quarter-score.js` 跑样例。样例 1 的核定总分必须是 89.2。

改完页面后强制刷新，避免旧脚本留在浏览器里。

## 1. 季度专项激励

1. 打开 `oa-pc/quarterly-wizard.html`。
2. 确认有专项激励和减分，没有原来的加分项。
3. 选「数量超越：超额完成 1 项核心关键指标」。自评分变为 1，并且不能改成 2。
4. 加到第 4 条时被拒绝。
5. 下季目标少于 3 条或多于 5 条时，提交被拒绝。
6. 打开月度填写页，确认没有专项激励。

## 2. 确认页字号和 HR 改分

1. 打开 `oa-pc/score-confirm.html`。
2. 绩效表正文、表头和分数是 14px。导航不必是 14px。
3. 在计划明细把一条已确认待办的最终总分从 89.2 改为 92.0，原因必填。
4. 回到确认页，能同时看到 89.2 和 92.0，采用分是 92.0，确认状态仍是已确认。

## 3. 退回保留填写

1. 在计划明细选一条已经全部确认、上级某格是 23 分的季度待办。
2. 退回到上级评分，填写原因。
3. 打开评分页，该格仍是 23。员工写过的内容还在。
4. 确认状态变为未确认。在上级重新提交前，这 23 分不作为当前有效分。

## 4. 评价人导入

1. 打开「评价人维护」。
2. 准备 3 行 CSV，第 2 行员工工号写成不存在的值。
3. 导入后成功行数是 0，错误里有第 2 行和那个工号。
4. 改成三行都有效后再导入，只有这三名员工的评价人变化。

导入格式见 [evaluator-import.md](contracts/evaluator-import.md)。

## 5. 保存和预览

1. 在季度填写页改一个字，点保存。3 秒内出现新的保存时间。
2. 地址栏加上 `autosaveMs=5000`，再改一个字，然后不再输入。约 5 秒后保存时间再更新一次。接着什么都不改，再等 5 秒，时间不再变。
3. 只滚动页面，不产生新的保存。
4. 最后一步打开预览，能看到本周期每个区块，预览里改不了字。

默认不等待时，自动保存是 2 分钟。`autosaveMs` 只缩短验收等待。

## 6. 计划和失效

1. 把计划名称改成另一张计划已有的名称，保存失败。
2. 把确认截止改到员工填写截止之前，保存失败。
3. 合法改名后，员工打开的仍是原来那张待办，标题是新名称。
4. 失效一名填写中的员工。该员工待办列表和领导待评里都没有这条。计划明细选「已失效」仍能打开原表。
5. 这个人可以被放进另一张计划。此时再恢复原来的待办，被拒绝，并写出冲突的计划名称。

## 7. 处理人、筛选、导出

1. 计划明细里搜不到「默认上级」。
2. 待上级评价的行，处理人是评价人姓名。没有评价人时是「未指定评价人」。
3. 筛选「待上级评价」和「已完成」，每一行的状态都和筛选项一致。
4. HR 从计划明细导出，领导从评分页导出。两张图片都能读完表头和全部分区，文件名含姓名和考核期。
