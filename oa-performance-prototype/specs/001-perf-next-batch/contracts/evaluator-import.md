# Contract: 评价人导入

**Page**: `prototype/oa-pc/hr-evaluators.html`

## 文件

UTF-8 CSV。第一行必须是：

```text
员工工号,上级工号,分管工号,员工姓名,上级姓名,分管姓名
```

后三列可以留空；分管工号留空表示该员工不设分管。编码不是 UTF-8，或表头对不上，整份文件拒绝，不写入。

## 校验顺序

先读完每一行，再决定写不写。出现下面任何一条，整批写入行数是 0，并列出行号、工号和原因：

- 员工工号在人员名单中不存在
- 上级工号在人员名单中不存在
- 分管工号非空但不在人员名单中
- 上级工号等于员工工号
- 分管工号等于员工工号
- 同一员工工号在文件里出现超过一次
- 填了员工姓名、上级姓名或分管姓名，但和该工号的主数据不一致

姓名留空时只看工号。

## 成功时

只更新文件里出现的员工。文件里没有的员工，原来的上级和分管都不变。

更新之后，这些员工名下还没完成上级评分的待办，当前处理人改为新上级；还在待分管评价的待办，当前处理人改为新分管。已经评完的那次评分，评分人姓名不改。

## 单条修改

页面上的组织架构选人使用和导入同一套校验：两列都不能是员工本人，工号必须存在。不通过就不保存这一行。清空分管时，已经进入待分管评价的任务要先由 HR 决定改派或退回，不能直接留空。
