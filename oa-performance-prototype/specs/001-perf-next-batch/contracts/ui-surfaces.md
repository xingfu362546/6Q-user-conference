# Contract: 页面行为

本期只改现有原型页面，并加一个评价人页面。小程序和 OA 上同一类动作保持同一结果。月度不出现专项激励。

## 员工填写

| 页面 | 行为 |
| --- | --- |
| `prototype/oa-pc/quarterly-wizard.html` | 8 步：专项激励、减分保留，删「绩效面谈」步。专项横表最多 5 条，每条可传 1 个图片/PDF 附件。下季目标 3 到 5 条，逐条选是否对标，无权重校验。最后一步可预览整表。每步有保存。变脏后 2 分钟自动保存 |
| `prototype/miniapp/quarterly-wizard.html` | 同上 |
| `prototype/oa-pc/monthly-wizard.html` | 只加预览和保存。区块不变 |
| `prototype/miniapp/monthly-wizard.html` | 同上 |

预览是只读层，使用和填写页相同的横表。从预览返回后停在提交前，内容还在。预览本身不代替提交校验。

保存失败时，最新保存时间不变，并提示未保存。地址栏 `autosaveMs=5000` 只用于把等待缩到 5 秒，默认 120000。

## 评分

| 页面 | 行为 |
| --- | --- |
| `prototype/oa-pc/supervisor-score-monthly.html` | 保存和自动保存。退回后原分数仍在输入框 |
| `prototype/oa-pc/supervisor-score-quarterly.html` | 同上，并显示专项行（含附件预览）。上级和分管只能打 0 到该档分值。最终得分列只读。不再出现面谈只读区和分管改总分入口 |
| 小程序领导评分页 | 与对应 OA 评分页同一份数据和同一套保存规则 |

领导端可以导出当前这名员工的整表 PDF。

## 确认

| 页面 | 行为 |
| --- | --- |
| `prototype/oa-pc/score-confirm.html` | 绩效表正文、表头、分数、页内说明 14px（合计区数值 18px）。显示四项：计算总分、上级核定、有修改时的 HR 最终总分、采用分；v1.5.3 起没有分管核定。只有待员工确认需要员工点确认，上级和分管提交评分即视为已确认。确认状态不因改分而改变 |
| `prototype/miniapp/score-confirm.html` | 同上 |

确认页没有自动保存，也没有草稿按钮。

## HR 计划

| 页面 | 行为 |
| --- | --- |
| `prototype/oa-pc/hr-plan-list.html` | 操作里增加编辑。表单弹窗可改名称和四个时间（含员工填写截止、上级评分截止），不可改类型、范围和奖金规则 |
| `prototype/oa-pc/hr-plan-detail.html` | 处理人显示真实姓名（上级和分管分列）。筛选为未开始、填写中、已逾期、待上级评价、待分管评价、待员工确认、已完成、已失效。可按状态退至、失效、恢复、改最终总分、导出 PDF |

退回必须选可退节点，原因必填。待上级评价只能退员工填写；待分管评价可退员工填写、上级评分；待员工确认可退三个评分节点（月度只有前两个）。员工填写中和已完成不出现退至。退回后确认作废，输入框里的内容和分数保留。

失效原因必填。员工端和领导端都不再列出这张待办。只从当前计划名单和本次发放范围包移除，其他计划与模板不变。原内容在「已失效」里仍可打开，但不能催办或再评分。恢复时该人已在本计划另一个范围包内则拒绝并写出范围包名称；恢复后节点是未开始。

改最终总分必须填原因，记录修改前采用分、修改后、人和时间。待员工确认和已完成都不阻止这次修改。

## 评价人

新页面 `prototype/oa-pc/hr-evaluators.html`，菜单放在「绩效管理」下，与计划管理并列，名称是「评价人维护」。

列：员工工号、姓名、部门、岗位、上级（评价人）、分管领导。上级和分管都从组织架构选人，选中后自动带出工号，不能手输；本人置灰。分管可清除。可以改单行，可以下载当前名单，可以按 [导入约定](evaluator-import.md) 批量修改。

## 员工和领导的列表

失效的待办不出现在员工待填写、逾期、进行中，也不出现在领导待评。恢复后从员工填写重新出现，节点是未开始。

## 导出文件名

`{员工姓名}-{考核期}.pdf`。PDF 包含表头和该周期全部区块，空区块也在。
