# Contract: 页面行为

本期只改现有原型页面，并加一个评价人页面。小程序和 OA 上同一类动作保持同一结果。月度不出现专项激励。

## 员工填写

| 页面 | 行为 |
| --- | --- |
| `prototype/oa-pc/quarterly-wizard.html` | 增加专项激励、减分、下季目标改为 3 到 5 条。最后一步可预览整表。每步有保存。变脏后 2 分钟自动保存 |
| `prototype/miniapp/quarterly-wizard.html` | 同上 |
| `prototype/oa-pc/monthly-wizard.html` | 只加预览和保存。区块不变 |
| `prototype/miniapp/monthly-wizard.html` | 同上 |

预览是只读层，使用和填写页相同的横表。从预览返回后停在提交前，内容还在。预览本身不代替提交校验。

保存失败时，最新保存时间不变，并提示未保存。地址栏 `autosaveMs=5000` 只用于把等待缩到 5 秒，默认 120000。

## 评分

| 页面 | 行为 |
| --- | --- |
| `prototype/oa-pc/supervisor-score-monthly.html` | 保存和自动保存。退回后原分数仍在输入框 |
| `prototype/oa-pc/supervisor-score-quarterly.html` | 同上，并显示专项行。上级和分管只能打 0 到该档分值。最终得分列只读 |
| 小程序领导评分页 | 与对应 OA 评分页同一份数据和同一套保存规则 |

领导端可以导出当前这名员工的整表图片。

## 确认

| 页面 | 行为 |
| --- | --- |
| `prototype/oa-pc/score-confirm.html` | 绩效表正文、表头、分数、页内说明 14px。同时显示系统汇总、上级核定、季度的分管核定、有修改时的 HR 最终总分、当前采用分。有 HR 最终总分时采用它。确认状态不因改分而改变 |
| `prototype/miniapp/score-confirm.html` | 同上 |

确认页没有自动保存，也没有草稿按钮。

## HR 计划

| 页面 | 行为 |
| --- | --- |
| `prototype/oa-pc/hr-plan-list.html` | 操作里增加编辑。可改名称和四个时间，不可改类型、范围和奖金规则 |
| `prototype/oa-pc/hr-plan-detail.html` | 处理人显示真实姓名。筛选增加待上级评价、已完成、已失效。可退回、失效、恢复、改最终总分、导出图片 |

退回必须选已经到达过的节点，原因必填。月度只有员工填写和上级评分。季度再加上分管评分。已全部确认也可以退。退回后确认作废，输入框里的内容和分数保留。

失效原因必填。员工端和领导端都不再列出这张待办。本期参与名单移除该人。原内容在「已失效」里仍可打开，但不能催办或再评分。恢复时如果该人已在另一张未结束计划里，拒绝并写出那张计划的名称。

改最终总分必须填原因，记录修改前、修改后、人和时间。分管已经改过核定总分、双方或三方已经确认，都不阻止这次修改。

## 评价人

新页面 `prototype/oa-pc/hr-evaluators.html`，菜单放在「绩效管理」下，与计划管理并列，名称是「评价人维护」。

列：员工工号、姓名、部门、岗位、评价人工号、评价人姓名。可以改单行，可以下载当前名单，可以按 [导入约定](evaluator-import.md) 批量修改。

## 员工和领导的列表

失效的待办不出现在员工待填写、逾期、进行中，也不出现在领导待评。恢复后按失效前的节点重新出现。

## 导出文件名

`{员工姓名}-{考核期}.png`。图片包含表头和该周期全部区块，空区块也在。
