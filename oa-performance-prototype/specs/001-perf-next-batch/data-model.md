# Data Model: 绩效下版本

**Feature**: `specs/001-perf-next-batch`  
**Date**: 2026-11-10

字段名用原型里已经在用的中文业务含义说明。不在这里定数据库表。

## 员工

已有人员。评价人和待办都用工号找人。

| 字段 | 规则 |
| --- | --- |
| 工号 | 唯一 |
| 姓名 | 展示用。导入时若填写且与工号不符，整批失败 |
| 部门、岗位、职级 | 职级用来乘建议金额系数 |

职级系数：专员 1.0，主管 1.1，经理 1.2，总监 1.3，副总经理 1.4。其他职级可以算档次，金额记为未匹配。

## 评价关系

一名员工最多一名评价人。评价人是另一名员工，表示直接上级。分管领导不在这张关系里。

| 字段 | 规则 |
| --- | --- |
| 员工工号 | 必填，必须存在 |
| 评价人工号 | 可空。有值时必须存在，且不能等于员工工号 |

改评价人之后：尚未完成上级评分的待办，当前处理人改为新评价人。已经提交的上级评分记录保持原评分人。

## 范围包模板

可复用名单。本期失效和恢复都不修改它的成员。

| 字段 | 规则 |
| --- | --- |
| 标识、名称 | 已有 |
| 成员工号列表 | 模板成员，不被单张待办失效改写 |

## 考核计划

| 字段 | 规则 |
| --- | --- |
| 标识 | 已有，如 `2026-05`、`2026-Q2` |
| 名称 | 去掉首尾空格后，不能和其他计划相同。与自己原来的名称相同可以保存 |
| 类型 | 月度或季度。编辑计划时不能改 |
| 启动时间 | 不晚于员工填写截止 |
| 员工填写截止 | 不晚于上级评分截止 |
| 上级评分截止 | 不晚于确认截止。季度的分管评分也用这个时间 |
| 确认截止 | 四个时间的最后一个 |
| 本期参与名单 | 发放时从所选范围包复制出来的工号。失效时移除，恢复时加回 |

## 绩效待办

一张计划里的一名员工。

| 字段 | 规则 |
| --- | --- |
| 计划标识、员工工号 | 合在一起唯一 |
| 节点 | 见下方状态 |
| 逾期 | 可与「未开始」「填写中」同时成立。判断用计划上的员工填写截止 |
| 失效 | 空，或含原因、操作人、时间。失效后员工端和领导端列表都不出现 |
| 确认 | 员工、上级、分管（仅季度）各自是否已确认 |
| HR 最终总分 | 空，或含分数、原因、修改前分数、修改人、时间。有值时对外采用它，确认状态不因此改变 |
| 退回记录 | 每次含目标节点、原因、操作人、时间 |
| 当前处理人 | 不入库成「默认上级」。按节点现算，规则见下表 |
| 填写文档、评分文档 | 退回时不删除。重新提交前，所选节点及其后的分数只显示、不算当前有效分 |

当前处理人：

| 节点 | 显示 |
| --- | --- |
| 未开始、填写中、退回到员工填写 | 员工姓名 |
| 待上级评价 | 评价人姓名；没有评价人时显示「未指定评价人」 |
| 待分管评价 | 分管领导姓名 |
| 待确认 | 还没确认的人员姓名，多个并列 |
| 已完成 | 「已完成」 |
| 已失效 | 「已失效」 |

### 节点怎么走

| 从 | 事件 | 到 |
| --- | --- | --- |
| 未开始 | 员工开始填写 | 填写中 |
| 填写中 | 员工提交并通过校验 | 待上级评价 |
| 待上级评价 | 上级提交评分 | 月度进入待确认；季度进入待分管评价 |
| 待分管评价 | 分管提交评分 | 待确认 |
| 待确认 | 应确认的各方都确认 | 已完成 |
| 已到达过的节点，含已完成 | HR 选择节点并填写原因 | 回到该节点，确认状态作废，字段值保留 |
| 除已失效外的任意节点 | HR 填写原因后失效 | 已失效，并从本期参与名单移除 |
| 已失效 | HR 恢复，且该员工没有占用另一张未结束计划 | 恢复到失效前的节点 |

退回到还没到达过的节点是不允许的。例如人还在填写中，不能退到分管评分。

筛选保持原有「全部、未开始、填写中、已提交、已逾期」，并增加「待上级评价、已完成、已失效」。这里的「已提交」只匹配节点正好是「已提交」的旧数据；新提交的员工待办直接进入「待上级评价」，不再停在含糊的已提交。

## 填写文档

月度文档保持现有区块：核心、常规、行为态度、加减分、总结、下月目标。不增加专项激励。

季度文档在现有核心、常规、6Q3J、面谈四段、自评总结之外增加：

### 专项激励申报

最多 3 条，可以 0 条。

| 字段 | 规则 |
| --- | --- |
| 关键目标、关键成果 | 选了超越类型就必须填。只有空格视为没填 |
| 附件 | 可空 |
| 超越类型 | 只能是规格对照表里的 20 项 |
| 自评分 | 由类型带出，不可改 |
| 上级评分、分管评分 | 0 到该档分值的整数 |
| 人才开发部最终得分 | 0 到该档分值的整数。未填时整张表的档次是「暂不认定（未评定）」 |

人才开发部可以额外追加 1 条「品牌价值」或「其它超越」，分值 0 到 3 的整数，必须有认定说明。这两类不出现在员工下拉框。

### 减分项

| 字段 | 规则 |
| --- | --- |
| 事件说明 | 有减分时必填 |
| 自评、上级、分管 | 小于等于 0。未填按 0 加权 |
| 综合分 | 由计分模块算出，不手填 |

### 下季核心目标

3 到 5 条。每条有关键目标、考核目标、考核标准、挑战或资源、是否跟上级对标（是/否）、备注。没有分数。

### 专项档次

由计分模块算出建议档次和建议金额。人才开发部可以改最终档次，必须填写原因。确认页同时显示建议档次和最终档次。

## 草稿

| 字段 | 规则 |
| --- | --- |
| 最新保存时间 | 只有保存成功才更新。从未保存时显示「尚未保存」 |
| 脏标记 | 内容变化后设上。保存成功后清除。滚动和翻页不设 |

确认页没有草稿。

## 关系

- 一个计划有一份本期参与名单，名单来自范围包模板的复制，之后与模板分开。
- 一个计划有多张待办，一张待办对应一名员工和一份填写文档、一份评分文档。
- 评价关系按员工工号挂到人，不挂到某一张计划。待办上的「当前处理人」在待上级评价时读取它。
- HR 最终总分挂在待办上，不覆盖填写文档里的原始自评和上级分。
