## 一、补的规则

### 改的条款

| 条款 | 改成什么 | 原因 |
| --- | --- | --- |
| FR-003 | 季度按自评 20%、上级 40%、分管 40%，分管未填或 0 分也不回退；月度固定 20/80，分管不参与 | 原文没限定周期，开发会按字面把月度也改成 20/40/40，月度最高只能到 60% |
| FR-004 | 季度减分同权重计算；月度减分沿用上级单人核定 | 同上 |
| FR-007 | 专项单条得分 = 上级 30% + 分管 30% + 人才开发部 40%；三方缺一方该条待评定；旧数据只有最终得分时直接采信 | 原文只用最终得分，上级和分管填了不参与，业务上说不通 |
| FR-013 | 确认页固定五项：计算总分、上级核定、分管核定、HR 最终总分、采用分；采用分按 HR 最终 → 分管核定 → 计算总分取值 | 原文把上级和分管合成一项，开发找不到上级核定取哪个数 |
| FR-024 | 待确认只显示员工和分管；上级提交即确认，不再出现在待确认 | 现网提交评分即置上级已确认，原文假设的场景不会出现 |
| FR-026 | 导出前先打开与预览相同的只读整表；空区块按任务创建时的模板快照读取 | 原导出只截局部，模板改过之后导出结构与员工看到的不一致 |

### 新增条款

- **FR-027 精度**：行综合分不单独取整；工作成果小计、减分小计、核定总分各保留 1 位（HALF_UP）；落库与展示同口径。
- **FR-028 有效分**：退至后，所选节点及其后的已提交分数转为作废快照，原格显示并标「已作废」；计算、确认、结果、导出、奖金只取有效分。
- **FR-029 确认页字段契约**：五项字段各自的数据来源和缺失时的显示方式固定下来。
- **FR-030 评价关系优先级**：发放取评价关系表；表空回退自动解析并提示；存量按最近任务回填；单任务改派不回写关系表；离职不自动改。
- **FR-031 失效落点与影响面**：失效只落在当前计划的待办上。只改当前计划的名单快照和这次发放的范围包；其他计划不变，范围包模板不改。完成率分母减失效人数；结果、催办、奖金、待办、统计都排除失效；已失效只读。
- **FR-032 保存不覆盖核定分**：任何评分保存（含自动保存）不得覆盖分管核定分；HR 最终分独立字段；草稿只写草稿字段。
- **FR-033 权限与幂等**：后端从登录态取角色并校验归属；非法状态明确报错；退至、失效、恢复、改分、导入幂等。
- **FR-034 计划编辑生效规则**：未关闭才可改；名称全库唯一；允许改到过去但二次确认并提示影响人数；写操作日志。

## 三、注释怎么对照

原型页面上这次新增或改变的地方，注释序号用绿色 `v1.5.2` 标签，抽屉内「过往逻辑」标上一版、「现在的逻辑」标 v1.5.2。开发读页面时直接打开注释，不必再对聊天记录。

跟进评审写在这些注释里：

| 页面 | 注释 | 开发要按这个做 |
| --- | --- | --- |
| 计划明细 | 注释 5，标签 v1.5.2 | 失效只移出当前计划的名单和这次发放的范围包。其他计划不变，范围包模板不改。不存在「影响多张计划」的二次确认 |
| 计划明细 | 注释 4，标签 v1.5.1 | 初始节点没有「退至」。不能选当前节点。已到达节点在进入时追加，退至不清空 |
| 确认页 | 注释 1，标签 v1.5.2 | 五项分开。上级核定是上级提交时的快照，缺失显示「—」。采用分按 HR 最终总分、季度分管核定、计算总分取值 |
| 评分页导出 | 计划明细注释 5 | 先看整表再导出。整表用这张待办的真实填报，没有填报就留空，不填示例分。文件名是「姓名-考核期.png」，考核期是 `YYYY-MM` 或 `YYYY-Qn` |

规则原文以 spec 的 FR-013、FR-014、FR-023、FR-026、FR-031 为准。本文件只说明改了哪一条。
